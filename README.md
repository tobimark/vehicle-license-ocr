# 行驶证结构化识别 Vehicle License OCR

专门针对**中国机动车行驶证**训练的字段级识别模型，将一张行驶证照片转化为结构化的字段信息。

目前互联网上没有专门针对中国行驶证训练并公开权重的开源模型——现有项目要么是车牌识别（ALPR），要么是调用百度/阿里/腾讯付费接口的客户端封装。本项目填补这个空白。

> 当前仓库仅作项目介绍，模型权重暂未公开发布，发布计划见文末路线图。

## 功能

输入一张行驶证照片（正页或副页），模型自动定位每个字段的区域并输出结构化信息，支持正页与副页混拍、旋转、透视倾斜的手机拍摄场景。

技术路线为两段式：

```
行驶证照片
  │
  ▼
字段定位：YOLOv8n-OBB 旋转框检测，按字段实际角度框出每个字段
  │
  ▼
文字识别：字段区域旋正裁剪后交给 OCR 引擎识别文本
  │
  ▼
结构化输出
```

输出示例：

```json
{
  "hphm":  {"zh": "号牌号码",     "text": "京A12345"},
  "clsbdh":{"zh": "车辆识别代号", "text": "LFV3A23C8K3123456"},
  "syr":   {"zh": "所有人",       "text": "张三"}
}
```

## 模型

| 模型 | 架构 | 类别数 | 输入 | 适用场景 |
|---|---|---|---|---|
| 全字段模型 | YOLOv8n-OBB | 19 | 640×640 | 整张行驶证照片，正页副页通用 |
| 副页模型 | YOLOv8n-OBB | 8 | 640×640 | 裁剪后的副页图，字段更少、精度更高 |

### 可识别字段（19 类）

| 类别 | 字段 | 类别 | 字段 |
|---|---|---|---|
| `hphm` | 号牌号码 | `hphm2` | 号牌号码（副页） |
| `cllx` | 车辆类型 | `syr` | 所有人 |
| `zz` | 住址（第一行） | `zz2` | 住址（第二行） |
| `syxz` | 使用性质 | `ppxh` | 品牌型号 |
| `clsbdh` | 车辆识别代号（VIN） | `fdjhm` | 发动机号码 |
| `zcrq` | 注册日期 | `fzrq` | 发证日期 |
| `dabh` | 档案编号 | `hdzrs` | 核定载人数 |
| `hdzzl` | 核定载质量 | `wkcc` | 外廓尺寸 |
| `zbzl` | 整备质量 | `zzl` | 总质量 |
| `zxbh` | 证芯编号 | | |

> 副页模型（8 类）为其中正副页共有的质量/尺寸类字段与 `hphm2`、`dabh`、`zxbh` 的子集。
> `zz`/`zz2` 拆成两行是因为住址经常换行，两行分别检测再拼接识别效果最好。

## 训练说明

- **数据规模**：约 5000 张真实行驶证图像，覆盖正页与副页
- **标注方式**：字段级旋转框（OBB）标注
- **训练框架**：Ultralytics YOLOv8n-OBB，输入 640×640，导出 ONNX 部署
- **数据合规**：训练数据包含真实证件信息，出于隐私与合规考虑，数据来源不公开、数据集不随项目发布

## 特点

- **旋转框（OBB）定位**：手机拍摄的行驶证普遍存在透视倾斜，水平框会切进相邻字段，本模型按字段实际角度定位，倾斜场景下裁剪更准
- **字段级结构化**：直接输出 19 类语义字段，无需从整页 OCR 文本中做规则后处理
- **本地推理**：模型体积约 12 MB，CPU 即可运行，数据不出服务器
- **成本优势**：替代按次计费的云端行驶证 OCR 接口（百度智能云、APISpace、石榴智能等）

## 适用场景

银行、保险、租车、二手车交易、汽配等需要证件信息录入，且不允许将客户证件上传第三方 API 的业务场景。
